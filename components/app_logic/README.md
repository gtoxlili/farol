# app_logic

The scene and the application logic. GSP renders the scene and runs every
motion (page flows, the drawer, the lamp, tweens); the Rust workspace in
`../../rust` decides everything else.

- `ui/main.json`: the scene, generated by `../../tools/ui/gen_scene.py` together
  with `rust/logic/src/scene.rs` (the typed tables of keys and binds). Edit the
  generator, then run `python tools/dev.py scene`. Fonts are subsets of Geist
  (Latin and digits, baked) and Noto Sans SC (`ui/fonts/`, built by
  `tools/fonts/build_fonts.py`).
- `CMakeLists.txt`: packs the scene into the deployable bundle for `ui_apps`
  (1 MB), enables FreeType and links the Noto Sans SC subset into the
  application image for runtime text, runs cargo for
  `riscv32imafc-unknown-none-elf` and links `libplatform.a`.
- `app_logic.c`: asserts `CONFIG_FREERTOS_HZ == 1000` and that the Rust bindings
  match the generated scene constants (`gsp_bindings_check.h`, written by
  `cargo xtask gen-gsp`); hands GSP the dynamic font.
- `Kconfig`: `CONFIG_FAROL_DEMO` (start on the built-in demo fleet, no Paseo)
  and `CONFIG_FAROL_BENCH` (the frame benchmark harness, `../app_bench`). Both
  are off in builds for use.
- `host/`: the simulator backend (a separate CMake project for sim_bridge) that
  links the Rust `host` crate; `host/checks/` holds scripted scenarios.

```c
ESP_ERROR_CHECK(app_logic_font_apply(&config));   /* before the UI starts */
/* ... esp_gsp_esp_lcd_start(&config, ...) ... */
if (app_logic_start(ui) != 0) { /* logic unavailable; UI and Recovery keep running */ }
```

## Contract

`app_logic_font_apply` copies the embedded font to PSRAM once (it stays until
reboot; on allocation failure the configuration borrows it from flash) and sets
`ttf`/`ttf_size`.

`app_logic_start` runs once on the caller's task after `esp_gsp_esp_lcd_start`.
It registers GSP's event, component and input-interceptor callbacks and creates
the `logic` task (16 KB stack in internal RAM, priority 5), the single owner of
the app state. Return values: 0, -1 null handle or second call, -2 queue
allocation, -3 callback registration, -4 task creation. Nothing is torn down:
the UI must live until reboot.

Threading: every callback (GSP's render task, the Wi-Fi, link and feedback
components' tasks) converts its input to a boxed event and posts it to a
24-entry queue without blocking; a full queue drops the newest event. The
`logic` task waits on that queue until the app's next deadline, then handles the
event and polls time-driven work. Its GSP setters are asynchronous: GSP queues
them and applies them before its next frame. The input interceptor reads one
atomic: a touch on a dark screen only wakes it. Rust allocations prefer PSRAM; a
Rust panic logs and aborts into ESP-IDF's panic path (core dump, reboot). The
first setter GSP rejects is logged once (tag `logic`); later ones are counted,
and a health line (unused stack, heaps, rejections) is logged every minute.

`app_logic_restart_demo(offset_ms)` restarts the demo fleet at a fixed moment,
for the bench harness; `app_logic_demo_build()` reports `CONFIG_FAROL_DEMO` to
Rust.

Saved state lives in the default `nvs` partition, namespace `farol`: `prefs`
(sound, vibration, brightness, automatic brightness) and `paseo` (the daemon
address and the daemon password, in plain text).

## Simulator

`python tools/dev.py sim` builds `host/` into a backend library and loads it into
the GSP simulator with the dynamic font; the Rust `host` crate runs the same
`logic::App` inline on the bridge's single thread and polls it from a 50 ms GSP
timer. It runs the demo fleet (`FAROL_SIM=welcome` starts on the first-boot page;
`FAROL_SIM_T=<ms>` starts the demo script that far in), emulates Wi-Fi scans and
joins (the password "wrong" fails), and prints the board's effects to stderr.
